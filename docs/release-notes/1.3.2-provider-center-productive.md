# Release 1.3.2 — Central de Provedores em Produção

## Objetivo
Tornar a Central de Provedores realmente funcional: adapters de dados agora usam credenciais por organização via `getProviderRuntimeConfig`, com fallback Org → Plataforma → Env legado.

## Mudanças

### Backend
- **`src/lib/providers/runtime-config.server.ts`** — resolver único que consolida credencial + metadados (priority, limites, status).
- **Casa dos Dados** (`casa-dos-dados.server.ts`) — aceita `baseUrl` do resolver; deixou de ler `process.env` na chamada.
- **Apify** (`apify.server.ts`) — `runApifyActor` aceita `baseUrl` opcional.
- **Kipflow** (`kipflow.adapter.server.ts`) — refatorado como **factory** (`createKipflowAdapter(orgId)`) que resolve chave/URL a cada capability. Singleton legado preservado.
- **Registry JCS Data Engine** — `getAdapter(name, orgId)` propaga a organização.
- **Prospecção** (`prospecting.functions.ts`) — Casa dos Dados e Apify agora usam `getProviderRuntimeConfig` em vez de env direto e da tabela legada `organization_integrations`.
- **Health check Kipflow** — corrigido para autenticação `x-api-key` + endpoint `/search` (era Bearer + `/health` inexistente).

### CRUD e UI
- Nova server fn `setProviderEnabled` — separa **Desativar** (preserva secret) de **Remover** (apaga cifrado).
- Botões distintos na tela: **Testar** · **Desativar/Ativar** · **Remover** (com confirmação).
- Diálogo de configuração ganhou campos **Limite diário** e **Limite mensal**.
- Badge "Desativado" quando `enabled=false`.

### Segurança
- Todos os segredos continuam cifrados AES-256-GCM em `provider_secret_vault`.
- Nenhuma chave volta ao navegador; apenas `last4`.
- Auditoria em `provider_audit_log` para `provider_enabled` / `provider_disabled`.

## Ativação
- Feature flag `tenant_provider_settings_enabled` habilitada para a organização **JCS** (piloto).
- Demais organizações continuam no fluxo legado até liberação.
