# Release 1.2.1 — Sprint 1 / PR 02
**Módulo:** JCS Enrichment Orchestrator — Hardening, Testes e Persistência
**Gate:** `jcs_data_engine_enabled` (nenhuma execução quando OFF)

## Objetivo
Corrigir as limitações apontadas no relatório do PR 01: persistência dedicada,
cancelamento distribuído, classificação de erros, retry seletivo, rate-limit
por provider, sanitização recursiva, ETA correto para plano paralelo e suíte
automatizada de testes. Nenhum fluxo operacional (Prospecção, Leads, CRM,
WhatsApp, Agenda, Cadências, Agentes, ICP, Produtos, Casa dos Dados, Apify,
Kipflow) foi tocado.

## Compatibilidade
- Aditivo. Nenhum consumidor externo do orquestrador (não há wiring) foi criado.
- `enrichment_jobs` continua sendo escrita (legado) e é usada como fallback de leitura em `getExecution`.
- Server Functions preservam contrato de entrada; `getExecution` agora retorna a linha de `enrichment_executions` (superset compatível).

## Rollback
1. `DROP TABLE public.enrichment_executions` (aditiva; nenhum outro objeto depende dela).
2. Reverter os arquivos alterados/criados listados acima.
3. `enrichment_jobs` mantém histórico anterior; nenhum dado é perdido.

## Riscos restantes
- Rate limiter é in-process: em múltiplas instâncias serverless cada worker aplica o próprio limite. Combinado com `checkBudget` (persistente), evita esgotar cota, mas não é global.
- Cancelamento consulta o banco a cada grupo/step; latência adicional em execuções muito curtas.
- Sem test-double para Supabase nos módulos `*.server.ts` que dependem dele (executions-store, orchestrator, planner, execution) — cobertura desses fica para o PR 03.
- Suíte de integração com providers reais (Kipflow) ainda não existe; nenhum crédito real é consumido nos testes automatizados.

## Pendências para o PR 03
