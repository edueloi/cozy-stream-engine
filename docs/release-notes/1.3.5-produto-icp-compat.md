# Release 1.3.5 — Correção de Compatibilidade Produto/ICP

## Causa raiz
`validateSearchAgainstIcp` tratava qualquer divergência de Segmento contra
regra `required: true, operator: "in"` do ICP como bloqueio objetivo. Como
Segmento é uma classificação comercial ampla e o CNAE é a classificação
técnica precisa, o cenário "Produto Firewall + Segmento Contabilidade +
CNAE 6920601" era bloqueado indevidamente mesmo quando o CNAE era aceito
pelo ICP.

## Arquivos alterados
- `src/lib/jcs-data-engine/smart-flow/validate.ts` — pré-cálculo de
  compatibilidade do CNAE (bloqueado / permitido por regra obrigatória /
  sem regra obrigatória). Divergências de `segmento` obrigatório são
  rebaixadas a `warning` (`broad_filter`) quando o CNAE informado é
  objetivamente compatível.
- `src/lib/jcs-data-engine/smart-flow/__tests__/validate-segmento-cnae.test.ts`
  — 5 novos testes cobrindo os cenários do hotfix.

Nenhum outro módulo tocado: motor Universal de ICP, Pré-Score, Score Final,
JCS Data Engine, Smart Flow, Enrichment Orchestrator, Provider Registry,
Casa dos Dados, Kipflow, Apify, Leads, Cadências, Agentes, WhatsApp, Agenda,
E-mail, Importações e fluxo legado permanecem intactos. Nenhuma migration.

## Comportamento anterior
- Segmento textualmente diferente do ICP → `blocked` + botão desabilitado.

## Comportamento novo
- CNAE proibido / desqualificador → continua `blocked`.
- UF, cidade, porte e situação cadastral obrigatórios violados → continua `blocked`.
- Segmento divergente **com CNAE compatível** → `warning`, botão habilitado
  (com confirmação de alertas), CNAE é declarado como critério principal.
- Segmento divergente **sem CNAE** → continua `blocked` (não há critério
  técnico para apoiar).
- Segmento vazio + CNAE compatível → compatível.
- Produto → seleciona ICP recomendado automaticamente; usuário pode trocar.

## Cenários bloqueados
CNAE proibido; CNAE desqualificador; UF obrigatória violada; cidade
obrigatória violada; porte proibido/desqualificador; situação cadastral
obrigatória violada; Segmento obrigatório divergente sem CNAE.

## Cenários convertidos em warning
Segmento obrigatório divergente com CNAE compatível; Segmento ausente
quando ICP exige e CNAE compatível está informado.

## Testes
`bunx vitest run src/lib/jcs-data-engine/smart-flow/__tests__/validate` —
**20/20 verdes** (15 existentes + 5 novos), sem chamadas a APIs reais.

## Compatibilidade
- ICPs só com `segment`, só com `cnae`, ou com ambos: suportados.
- Produtos sem ICP: fluxo manual como antes.
- Pesquisas antigas: nenhum recálculo, nenhum dado histórico alterado.
- Pré-Score e Score Final continuam sendo a fonte de verdade após iniciar.
- Thresholds 60/80 inalterados.

## Rollback
Reverter `src/lib/jcs-data-engine/smart-flow/validate.ts` para a versão
anterior. Os testes novos podem ser removidos ou mantidos (falharão até o
revert do validate). Nenhuma migração precisa ser desfeita.
