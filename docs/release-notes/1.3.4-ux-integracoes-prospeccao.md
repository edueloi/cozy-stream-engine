# Release 1.3.4 — UX Integrações de Prospecção

## Objetivo
Eliminar o conceito de "Central de Provedores" para o usuário final. Toda a configuração das fontes de dados passa a ocorrer em **Prospecção → Integrações**, em um único lugar consistente.

## Escopo
Apenas UX. Nenhuma alteração de backend, banco, Provider Registry, Runtime Config, adapters, feature flags, Smart Flow, JCS Data Engine, ICP ou regras de negócio.

## Alterações
- `src/routes/_authenticated.prospecting.tsx`
  - Componente `Integrations` reescrito. Passa a listar todos os providers configuráveis (Casa dos Dados, Kipflow, Apify, Google Maps, LinkedIn Empresas/Pessoas, Instagram Empresas, Sites Corporativos, API REST Personalizada, Webhook) usando as server functions já existentes: `listProviders`, `saveProviderCredential`, `deleteProviderCredential`, `testProviderConnection`, `setProviderEnabled`.
  - Cards padronizados com: Status (Conectado / Desconectado / Credencial inválida / Saldo insuficiente / Rate limit / Indisponível / URL inválida / Desativado), API Key mascarada (`••••XXXX`), URL base, prioridade, timeout, limite diário e mensal, ativo.
  - Ações por card: Configurar, Testar conexão, Ativar/Desativar, Remover.
  - Origem da credencial exibida após teste (Organização / Plataforma / Legacy).
  - Providers sem adapter funcional (Apollo, Hunter, Dropcontact, RocketReach, People Data Labs, NeverBounce, ZeroBounce) permanecem ocultos até haver adapter oficial.
  - Painel "Resumo das Integrações" no rodapé com indicadores: providers ativos, providers com erro, saldo baixo, última sincronização.
  - Removido card antigo "Apify" isolado; o Apify agora aparece no mesmo padrão dos demais.
- `src/routes/_authenticated.settings.tsx`
  - Removido o botão **"Abrir Central de Provedores"**. O card em Configurações agora apenas informa que a configuração de integrações vive em Prospecção → Integrações.

## Compatibilidade
- A rota `/_authenticated/settings/providers` foi mantida internamente (nenhum arquivo foi apagado), apenas deixou de ser referenciada pela UI.
- Nenhuma migration. Nenhuma alteração em `provider_credentials`, `provider_secret_vault`, `provider_audit_log`, `app_settings`.
- O teste de conexão continua chamando o mesmo runtime usado pela prospecção (`resolveProviderCredential` → `healthCheck`), sem fluxo paralelo.
- Feature flag `tenant_provider_settings_enabled` continua governando a exibição do painel: quando OFF, a aba mostra mensagem de rollout controlado.

## Segurança
- API Key nunca retorna ao navegador — apenas `last4`.
- Campo de chave em branco no diálogo preserva a credencial atual (comportamento herdado).
- Segredos permanecem cifrados no vault AES-256-GCM.

## Riscos / Regressões
- Nenhuma alteração de regra de negócio.
- O restante da aba Prospecção (Nova Prospecção, Importar Base, Histórico) não foi tocado.

## Critério de aceite
O administrador consegue configurar todas as integrações de prospecção em um único lugar (Prospecção → Integrações), sem precisar acessar uma Central de Provedores separada.

## Testes manuais sugeridos
1. Configurar Casa dos Dados → Salvar → Testar conexão → Status "Conectado".
2. Configurar Kipflow → mesmo fluxo.
3. Configurar Apify → mesmo fluxo.
4. Alterar prioridade e limites → reabrir tela → valores persistem.
5. Desativar um provedor → status "Desativado", botão de teste desabilitado.
6. Reativar → status volta a "Aguardando teste".
7. Remover credencial → card volta ao estado "Desconectado".
8. Chave permanece mascarada em todas as telas.
9. Prospecção continua funcionando normalmente após todas as operações acima.
